# 全国詩吟イベントナビの週次更新

毎週月曜日の午前9時（日本時間）に、このCodexタスクの予約から実行する。既存の過去情報補完の予約を引き継ぎ、週次の新着確認と低優先のアーカイブ補完を一つの処理で行う。

予約はローカルのCodexで動作する。実行時にはPCの電源、ネット接続、Codexアプリの起動、作業フォルダとGitHubへのアクセスが必要。サイト自体はCloudflare Pagesで継続公開される。

## 毎回の調査

1. `README.md`、`FACT_CHECK.md`、`BACKLOG.md`、既存の `events/events.json` と直近の調査記録を確認する。既存IDと2022年1月以降の保存済み記録は維持する。
2. 今後12か月の新着催事を調べる。全国吟詠コンクール、クラウン吟詠コンクール、クラウンのリサイタル、全国優秀吟者大会を毎回確認し、既存データの主催者・会場の出典を調査先の起点にする。
3. 直近60日以内の掲載予定について、開催日・会場・中止や延期・観覧条件の変更を優先確認する。日程の経過だけで確認日を書き換えない。
4. 北海道・東北・関東・甲信越・北陸・東海・近畿・中国・四国・九州・沖縄の各地方で、新しい大会・コンサート・発表会の公開案内を探す。未掲載県を優先して補う。地域区分の正本は `events/regions.json`。
5. 主催者、会場、自治体、関係団体の公開案内を優先し、必要なら主催者の公開X・Facebook投稿を参照する。検索結果の要約だけで確定せず、元ページまたは資料を読む。閲覧できない資料は未確認として記録する。
6. 収集とは別の工程として `FACT_CHECK.md` の原文再照合を行う。追加・修正した全催事に項目別の精査記録を残す。既存の予定も開催が近いものから再点検し、矛盾や不明点を推測で埋めない。
7. 新着・訂正と既存予定の再点検が済んでから、2022～2025年の不足分を少しずつ補完する。進めた大会・年度と未解決事項を `BACKLOG.md` に記録する。

## 掲載判断

- 開催日・都道府県・会場を裏付けられた情報から掲載する。年違いの告知や過去の開催実績を今年の予定として使わない。
- 同じ大会名・日付・会場の重複を確認し、訂正は既存IDへ反映する。年度違いの開催は別IDにする。
- 観覧料と出場参加費を区別する。観覧可否、料金、開演時刻が分からないときは未確認のままとする。ユーザーの判断済み内容は、明確な新しい根拠なしに上書きしない。
- 中止・延期が判明した情報は記録を保持して表示を訂正し、通常の開催予定として誤案内しない。
- `checked_at` はその催事の資料を実際に読んだ日、`updated_at` は掲載データを確認・更新した日とする。表示の変更だけで調査日を更新しない。
- 調査したURL、追加・訂正ID、見つからなかった項目、確認できなかった資料を、リポジトリ外の `../output/research/shigin-events-weekly/YYYY-MM-DD/` に残す。個人連絡先やログイン情報は追加収集しない。

## 検査と公開

1. 既存の未コミット変更と並行作業を確認し、他の変更を混ぜない。必要なら一時worktreeで作業する。更新前のコミットSHAを控える。
2. `python -X utf8 scripts/events/render.py` でHTMLと内容別ファイル名のCSS/JSを生成する。
3. `python -X utf8 scripts/events/check-reviews.py --base <更新前SHA>`、`python -X utf8 scripts/events/test-reviews.py`、`python -X utf8 scripts/events/check.py` と `node scripts/events/check-ui.cjs`、`git diff --check` を実行する。新規催事も地域・予定・アーカイブの条件に合うことを確認する。精査記録を作るために出典を読んだふりをしない。
4. データ・精査記録 `scripts/events/reviews.json`・生成HTML・参照中のCSS/JS・必要な調査管理ファイルをまとめてコミットし、既存の `main` → GitHub Actions → Cloudflare Pages で公開する。公開前の自動検査が失敗したら公開を止め、原因を直す。検査を無効にして通さない。
5. デプロイ成功と公開ページへの反映を確認する。失敗した場合は公開完了と扱わず、原因と未反映の範囲を伝える。

意味のある追加・訂正・補完を公開したときだけ、件数と主な変更点を簡潔に知らせる。情報が変わらず対応不要なら通知しない。実行失敗やユーザーの判断が必要な場合は、その点を知らせる。網羅できていない情報を「全国すべて確認済み」と表現しない。
